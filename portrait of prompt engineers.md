# Портреты prompt-инженеров (PE)
Портреты нужны для оценки профессионального уровня специалистов — они делают развитие специалистов более прозрачным.

**Портреты инженеров описаны по существующим в Точке грейдам:**
- Junior
- Middle
- Middle+
- Senior

**Каждый уровень описан по блокам:**
- Задачи.
- Ожидания от роли.
- Что нужно для перехода на следующий грейд.
- Чего стоит избегать.

### Как работают портреты инженеров:
- Информация в каждом блоке следующего грейда добавляется к предыдущему. Например, функционал инженера Middle+ — это суммированные задачи и ожидания от Junior и Middle, на которые наслаиваются задачи и ожидания от Middle+.
- Если специалисту в команде не нужен какой-то навык, то его можно не учитывать. Для повышения грейда не обязательно закрывать всё, что описано в портретах.

## Junior
### Навыки
- Умеет писать промпты для рабочих задач: работает в процессах исследования гипотез и разработки сервисов с LLM.
- Знает базовые инструменты LLM: знаком с основами и может адаптировать готовые решения с function calling, json mode, json schema для structured outputs.
- Пишет код на Python. Обладает базовыми знаниями Python: например, чтение/запись файлов, простые функции. 
- Знает синтаксис json и может составлять примитивные запросы, использует синтаксис для создания json-схем и structured outputs. Может собрать ноутбук из готовых блоков для тестирования решения.
### Ожидания от роли
PE-инженер:
- Готовит датасеты — анализирует, собирает и дорабатывает список тест-кейсов для задачи.
- Тестирует промпты — самостоятельно проверяет качество ответов при отладке промптов.
- Тестирует качество ответов после встраивания — знаком с логированием LLM API, может проверить качество ответов и проконтролировать встраивание промптов/function calling в коде сервиса.
### Что нужно для перехода на следующий грейд
- Начать контролировать риски: для этого нужно знать требования юристов по работе с LLM и понимать, когда и с кем нужно проконсультироваться по сложным моментам.
- Познакомиться с процессом ревью промптов и начать его проводить.
- Выбрать дополнительную специализацию. Для роста нужно освоить другие перки по основной роли. Например, к PE-разработчику будут близок PE-архитектор, PE-универсал на старте. 
### Чего стоит избегать
- Самостоятельного принятия решений. Во время выбора моделей и реализации своей части в сервисе нужно консультироваться с коллегами выше грейдом.
- Написания бэкенд-сервисов и инфраструктуры: это не входит в задачи роли.

## Middle
### Навыки
- Умеет писать системы промптов для различных бизнес-сценариев: работает в процессах исследования гипотез и разработки сервисов с LLM.
- Знает основные инструменты LLM: пишет с нуля функции для function calling и json-схемы для structured outputs.
- Пишет код на Python: уверенно владеет Python, умеет разбираться в сложных кодовых структурах. Знает, как подключать LLM через API и разрабатывать базовые приложения с системой промптов, function calling, tools calling, json-схемами. Работает с RAG и может интегрировать его в решения команды.
### Ожидания от роли
PE-инженер:
- Готовит датасеты — анализирует, собирает и дорабатывает список тест-кейсов для задачи.
- Тестирует промпты — самостоятельно проверяет качество ответов при отладке промптов.
- Тестирует качество ответов после встраивания — знаком с логированием LLM API, может проверить качество ответов и проконтролировать встраивание промптов/function calling в коде сервиса.
- Проводит ревью промптов для коллег из своей команды.
- Контролирует риски: знает требования юристов по работе с LLM и понимает, когда и с кем нужно проконсультироваться по сложным моментам.
- Уверенно работает с задачами второго перка: самостоятельно решает задачи по выбранной дополнительной специализации.
### Что нужно для перехода на следующий грейд
- Выбрать дополнительную специализацию. Для роста нужно освоить другие перки по основной роли. Например, к PE-разработчику будут близок PE-архитектор, PE-универсал на старте. 
- Научиться оценивать гипотезы.
### Чего стоит избегать
- Написания бэкенд-сервисов: разработка backend-части сервисов и инфраструктуры не входит в задачи роли.

## Middle+
### Навыки
- Проектирует архитектуру взаимодействия LLM с другими компонентами системы: работает в процессах исследования гипотез и разработки сервисов с LLM.
- Знает инструменты LLM от разных поставщиков: с нуля пишет функций для function calling и json-схемы для structured outputs.
- Пишет код на Python: пишет сложные функции на Python и разрабатывает инструменты для интеграции LLM. Умеет подключать LLM через API и разрабатывать базовые приложения с системой промптов, function calling, tools calling, json-схемы. Работает с RAG и может интегрировать его в решения команды.
### Ожидания от роли
PE-инженер:
- Готовит датасеты — анализирует, собирает и дорабатывает список тест-кейсов для задачи.
- Тестирует промпты — умеет делать автоматизированное тестирование для детерминированных задач (тегирование, классификация, парсинг).
- Тестирует качество ответов после встраивания — знаком с логированием LLM API, может проверить качество ответов и проконтролировать встраивание промптов/function calling в коде сервиса.
- Проводит ревью промптов для коллег из своей команды.
- Контролирует риски — знает требования юристов по работе с LLM и понимает, когда и с кем нужно проконсультироваться по сложным моментам. Знает, что такое ДоД, может проходить его с кейсами команды.
- Уверенно работает с задачами двух и более перков — решает задачи выбранных специализаций без дополнительной помощи.
- Оценивает гипотезы — может самостоятельно оценить идеи команды по регламенту.
### Что нужно для перехода на следующий грейд
- Нужно выбрать дополнительную специализацию и освоить перки к основной роли: основная специализация + три и более дополнительных перков.
### Чего стоит избегать
- Написания бэкенд-сервисов: разработка backend-части сервисов и инфраструктуры не входит в задачи роли.
